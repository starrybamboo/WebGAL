# Spec：WebGAL 角色管理与静态组合立绘

> `composeFigure` Demo、`-composite` 参数为个人维护的立绘合成分支的实验性命令，如果看到请无视~~

来源：<https://github.com/OpenWebGAL/WebGAL/issues/1010>

方向修正：<https://github.com/OpenWebGAL/WebGAL/issues/1010#issuecomment-5078678535>

## Problem Statement（问题陈述）

WebGAL 当前以单张 figure 和位置槽位为主要立绘管理对象。静态差分角色通常由身体、服装、表情等位图按固定顺序叠加而成，作者若为每种组合预先导出整图，会增加资源数量和维护成本。

现有私有分支中的 `composeFigure` Demo 和 `-composite` 参数验证了浏览器合成的可行性，但它们不是面向 WebGAL 主分支的正式接口，也没有解决“同一个角色在舞台上只能存在一个”“后续命令继续操作该角色”等角色管理问题。

需要一套以“角色”为目标对象的新脚本语义：作者通过角色名和有序组合项选择角色当前立绘；引擎将静态部件合成为普通图像，再复用现有 figure 的位置、变换、效果和动画能力。模板和图像准备不能阻塞剧本或读档流程，首期也不承担浏览器持久化缓存的复杂度。

## Solution（解决方案）

新增 `character` script，使用紧凑的角色组合选择符：

```webgal
character: yuki/summer_uniform,face_smile -left;
```

斜杠前的 `yuki` 是舞台唯一的角色身份，斜杠后是逗号分隔的有序组合项。组合项可以引用静态部件或组合预设；预设在引用位置递归展开，展开后的顺序就是图层叠加顺序，重复项保留。

同名角色在舞台上最多存在一个。后续 `character: yuki` 或带新组合列表的同名命令继续操作该角色，而不是创建第二个实例。角色层管理身份和组合状态，底层 figure 继续负责位置、变换、效果、动画和最终渲染。

角色模板位于 `game/figure/<角色名>/figure.json`。模板 JSON 只作为组合定义输入，不作为 figure URL；组合完成后，引擎向 figure 系统交付一张普通图像。因此角色模板不会进入普通 `.json` 立绘的 Live2D 判定路径。

首期只使用进程内模板缓存、组合结果缓存和进行中任务去重，不写入 IndexedDB、`localforage`、磁盘或持久化 WebP。模板读取、部件加载、合成以及读档恢复均为非阻塞操作；即使目标图像尚未准备好，游戏流程也继续执行。

## User Stories（用户故事）

1. 作为剧本作者，我希望用角色名和组合列表直接写出 `character` 命令，以便在一条简洁语句中指定角色身份、立绘组合和舞台参数。
2. 作为剧本作者，我希望同名 `character` 命令始终操作同一个舞台角色，以便更新角色而不会意外生成重复实例。
3. 作为剧本作者，我希望省略组合列表时仍能继续操作已经存在的角色，以便只改变位置、效果或动画而不重新声明立绘组合。
4. 作为剧本作者，我希望更换同一角色的组合列表时仍然保持角色身份，以便自然表达换装、表情变化和状态切换。
5. 作为剧本作者，我希望 `character` 支持 figure 已有的绝大多数位置、变换、效果和动画参数，以便复用既有演出知识和素材。
6. 作为模板作者，我希望在角色目录中集中声明画布、静态部件和组合预设，以便让一个角色的资源结构保持内聚。
7. 作为模板作者，我希望组合项按书写顺序和预设展开顺序叠加，以便明确控制遮挡关系。
8. 作为模板作者，我希望重复引用的部件不会被隐式去重，以便表达需要重复绘制的特殊效果。
9. 作为模板作者，我希望预设可以递归复用其他预设，以便减少常用服装、身体和表情组合的重复声明。
10. 作为模板作者，我希望未来能够在同一组件组中声明多个变体，例如 `face.smile` 和 `face.sad`，以便为后续局部切换表情预留稳定的模板方向。
11. 作为玩家，我希望角色资源尚未加载或合成完成时游戏仍能继续，以便网络或设备性能不会让剧本流程停顿。
12. 作为玩家，我希望读档后游戏立即恢复流程，即使部分角色组合仍在后台准备，以便读档体验与普通立绘保持一致。
13. 作为引擎维护者，我希望角色模板 JSON 不进入普通 figure 的资源类型判断，以便避免被误认成 Live2D 模型。
14. 作为引擎维护者，我希望相同模板和相同组合的并发请求共享一个任务，以便避免重复加载和重复 Canvas 合成。
15. 作为引擎维护者，我希望过期的异步组合结果不能覆盖同一角色的最新请求，以便快进和连续换装时舞台状态保持正确。
16. 作为引擎维护者，我希望组合完成后只向 figure 系统交付普通图像，以便不复制现有立绘渲染、变换和动画实现。
17. 作为既有游戏作者，我希望原有 `changeFigure`、普通图片、Live2D 和 Spine 行为保持不变，以便现有剧本无需迁移。
18. 作为 Terre 作者，我希望编辑器能够维护角色模板并生成 `character` 命令，以便作者无需手写易错的模板和组合选择符。
19. 作为测试维护者，我希望能从一条完整 `character` 场景语句验证角色状态和 figure 交付结果，以便测试外部行为而不是内部缓存或 Canvas 调用细节。

## Implementation Decisions（实现决策）

- 新增独立的 `character` script；正式语法为 `character: <角色名>/<组合项>[,<组合项>...] [figure 参数...];`，不使用 `-preset` 参数。
- 角色名是舞台角色身份。同名角色最多存在一个，位置和底层 figure 目标只是角色当前状态，不参与角色唯一性判断。
- 不带组合列表的同名调用保持当前组合，只应用本次显式提供的 figure 参数；首次调用没有组合列表时记录作者错误，不创建不完整角色。
- 斜杠后的组合项可以引用静态部件或组合预设。预设在引用位置递归展开，顺序保留，重复引用保留；缺失引用和循环引用属于模板错误。
- `character` 复用 figure 支持的静态图片位置、变换、滤镜、层级、混合模式和进出场动画机制。组合变化只替换角色当前普通图像，不改变角色身份。
- 角色模板使用版本化 `figure.json`，声明组合画布、静态部件和组合预设。部件路径相对模板目录解析，首期只参与静态位图合成。
- 组合采用普通 `source-over` 顺序叠加，越出组合画布的像素裁剪，输出尺寸等于模板画布并保留透明通道。
- 角色层负责模板读取、校验、预设展开、异步合成和角色状态；figure 层只接收最终普通图像及演出参数。
- `figure.json` 永远不作为 figure URL。普通 `.json` figure 的 Live2D 识别逻辑保持原行为。
- 模板读取、部件加载、组合合成、首次显示和读档恢复均不阻塞剧本执行。实现复用普通立绘的非阻塞加载策略，而不是增加等待组合完成的全局屏障。
- 同一游戏进程内缓存已校验模板、已生成组合和进行中的同键任务。游戏刷新或进程结束后缓存失效。
- 首期不写入浏览器持久化存储；不引入 `localforage`、IndexedDB 组合库、持久化 WebP、缓存开关或清理按钮。
- 可在现有资源预取窗口中异步读取角色模板、预取其部件并低优先级预热组合；实际可见请求优先，预热不得阻塞游戏。
- 每个角色的异步组合请求需要可比较的新旧世代；完成的旧任务可以进入本轮缓存，但不得覆盖该角色的最新组合状态。
- 存档保存角色名、原始组合列表、位置和 figure 演出状态，不保存 Blob URL、Canvas、Pixi 纹理或其他运行时对象。
- 读档立即恢复逻辑角色状态并异步重建组合；单个角色失败不能中止其他舞台对象恢复，也不能阻塞后续剧本。
- `components.<group>.<variant>` 作为后续局部部件切换的模板扩展方向。首期不定义局部切换命令，也不在运行时维护独立可演出的部件树。
- 既有 `changeFigure` 继续处理普通图片、Live2D、Spine 和旧剧本，不承担正式角色组合语法。
- 私有 `composeFigure` Demo、`-composite` 参数及其专用解析、缓存和测试不进入主分支兼容范围，可以删除。
- Terre 需要能够识别和生成 `character` 命令，并提供角色模板的编辑、校验和预览能力；具体交付批次以角色模板 ABI 稳定为前提。

## Testing Decisions（测试决策）

- 主测试缝隙只有一个：输入包含 `character` 的完整场景语句，执行到角色管理层，观察角色逻辑状态以及最终交给 figure 的普通图像和演出参数。
- 主缝隙测试只断言外部行为：角色唯一、组合选择、figure 参数、非阻塞执行、异步结果新旧顺序和存档恢复；不直接断言私有 `Map`、Promise 队列、Canvas 绘制调用次数或内部 Pixi 对象结构。
- 解析器测试沿用现有场景解析测试模式，覆盖命令识别、角色名、组合列表、figure 参数、空列表和非法选择符。
- 规则层只保留必要的纯测试，覆盖有效模板、缺失引用、循环引用、递归展开、绘制顺序、重复项和路径边界。
- 运行时测试覆盖同名角色重复调用不会产生第二个实例，换组合时仍操作同一角色，以及不同角色可以独立存在。
- 非阻塞测试使用可控的未完成模板、图片或合成 Promise，验证命令执行和读档流程已经继续；Promise 完成后再验证最新角色状态被应用。
- 竞态测试先发起旧组合，再发起新组合，并让旧任务最后完成，验证旧结果不能覆盖新组合。
- 缓存测试通过重复发起同键请求观察只产生一个外部合成结果；失败请求不得成为永久失败缓存，后续请求可以重试。
- figure 边界测试验证角色模板 JSON 从未传入普通 figure 资源解析，而合成结果以普通图片进入现有立绘路径。
- 兼容性测试覆盖既有 `changeFigure` 图片、Live2D 和 Spine 语句，确认新增命令不改变原有解析和运行时行为。
- Terre 测试覆盖模板校验、组合预览和生成的 `character` 语句能够被引擎解析；不依赖编辑器内部组件层级。

## Out of Scope（非目标）

- 浏览器持久化组合缓存、磁盘缓存、IndexedDB、`localforage`、持久化 WebP 编码、玩家缓存设置和缓存清理。
- 本轮内存缓存的 LRU、容量上限、内存池和自动回收策略。
- 阻塞剧本、读档或舞台恢复直到角色组合完成。
- 将 `figure.json` 作为普通 figure URL，或修改既有 `.json` Live2D 路径语义。
- 合成 GIF、APNG、视频、SVG、Live2D、Spine 或多个动态模型。
- 首期的部件级独立演出、局部替换命令、口型、眨眼和运行时部件树。
- 同名角色的多个舞台实例，以及通过旧 `changeFigure` 或私有 `composeFigure` 入口创建正式组合角色。
- 对无效手写模板进行隐式修复或尽力兼容。
- 运行时文件监听，以及自动发现 Terre 外直接替换的部件文件。
- 把共享规则包、Node 指纹工具或资源指纹算法作为首期交付的硬性前提。

## Further Notes（补充说明）

- 本规格覆盖 Issue #1010 正文中与后续仓库成员评论冲突的方向：组合入口由 `changeFigure` 改为 `character`，舞台对象由位置或 figure ID 改为角色，持久化缓存退出首期范围，读档恢复不再等待组合完成。
- 评论中的 `character: yuki -preset=summer_uniform -left;` 是方向示例；后续讨论确定正式书写采用 `character: yuki/summer_uniform,xxx,yyy -left;`。
- `components.<group>.<variant>` 只承诺模板演进方向。默认变体、局部切换参数、组内互斥规则和缓存键扩展需要后续单独规格。
- 建议 WebGAL 与 Terre 共享模板校验、组合选择符解析、预设展开和缓存输入规范化规则。版本化纯 TypeScript 规则包与 Node 校验/指纹工具仍是建议，不是本规格的强制实现方式。
- 本地维护分支与 WebGAL 主分支并不完全一致。实施时只删除与私有 `composeFigure` Demo 和 `-composite` 参数直接相关的代码，不自动删除其他私有功能。
