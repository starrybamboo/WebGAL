# Spec：WebGAL 角色管理与静态组合立绘

> `composeFigure` Demo、`-composite` 参数为个人维护的立绘合成分支的实验性命令，如果看到请无视~~

来源：<https://github.com/OpenWebGAL/WebGAL/issues/1010>

方向修正：<https://github.com/OpenWebGAL/WebGAL/issues/1010#issuecomment-5078678535>

## Problem Statement（问题陈述）

WebGAL 当前以单张 figure 和位置槽位为主要立绘管理对象。静态差分角色通常由身体、服装、表情等位图按固定顺序叠加而成，作者若为每种组合预先导出整图，会增加资源数量和维护成本。

现有私有分支中的 `composeFigure` Demo 和 `-composite` 参数验证了浏览器合成的可行性，但它们不是面向 WebGAL 主分支的正式接口，也没有解决“同一个角色在舞台上只能存在一个”“后续命令继续操作该角色”等角色管理问题。

需要一套以“角色”为目标对象的新脚本语义：作者通过角色名和有序组合项选择角色当前立绘；引擎将静态部件合成为普通图像，再复用现有 figure 的位置、变换、效果和动画能力。模板和图像准备不能阻塞剧本或读档流程，首期也不承担浏览器持久化缓存的复杂度。

## Solution（解决方案）

新增 `character` script，使用紧凑的角色组合选择符：

```webgal
character: yuki/summer_uniform,face_smile -id=4 -transform={"position":{"x":420,"y":0}};
```

角色可以按身份清除，也可以一次清除全部由 `character` 管理的角色：

```webgal
character: yuki -clear;
character:none;
```

斜杠前的 `yuki` 是舞台唯一的角色身份，斜杠后是逗号分隔的有序组合项。组合项可以引用静态部件或组合预设；预设在引用位置递归展开，展开后的顺序就是图层叠加顺序，重复项保留。

同名角色来源在当前 Figure Target 中最多存在一个。每条非清除 `character` 命令都重新声明完整组合列表；引擎先移除其他目标中的同名角色来源，再把本次角色来源描述写入目标 ID。另一个 `character` 或普通 `changeFigure` 写入同一 ID 时只发生普通的同目标替换，不需要修改平行的角色状态，因为不存在独立角色状态集合。

角色模板位于 `game/figure/<角色名>/figure.json`。模板 JSON 只作为组合定义输入，不作为 figure URL；组合完成后，引擎向 figure 系统交付一张普通图像。因此角色模板不会进入普通 `.json` 立绘的 Live2D 判定路径。

角色模板的静态部件支持三种互斥尺寸模式：省略尺寸字段时使用图片原始尺寸；只提供正数 `scale` 时按原始尺寸等比缩放；成对提供正数 `width`、`height` 时按精确尺寸绘制并允许非等比拉伸。只提供一个精确尺寸或把精确尺寸与 `scale` 混用属于模板错误。

角色模板顶层 `canvas` 是直接选择部件和旧列表预设的兼容回退。对象形式的组合预设可以用 `{ "canvas": { "width": ..., "height": ... }, "items": [...] }` 声明自己的画布；这允许同一个稳定角色身份下的不同立绘组，各自使用该组默认底图的裁剪后尺寸作为合成坐标系。

对象预设还可以在自己的最终画布坐标系内声明可选 `facialRig`。组合底图表示睁眼与闭嘴，替换片只描述位图呈现资源；Character 来源适配器把该描述交给位图面部适配器。统一 Figure 面部运行时负责独立的语音轨道与眨眼轨道，并以原子面部姿态驱动 Character 位图；它不接管 Live2D 或 Spine，运行时、轨道和姿态都不会写入 StageState 或存档。

首期只使用进程内模板缓存、组合结果缓存和进行中任务去重，不写入 IndexedDB、`localforage`、磁盘或持久化 WebP。模板读取、部件加载、合成以及读档恢复均为非阻塞操作；即使目标图像尚未准备好，游戏流程也继续执行。

## User Stories（用户故事）

1. 作为剧本作者，我希望用角色名和组合列表直接写出 `character` 命令，以便在一条简洁语句中指定角色身份、立绘组合和舞台参数。
2. 作为剧本作者，我希望同名 `character` 命令始终操作同一个舞台角色，以便更新角色而不会意外生成重复实例。
3. 作为剧本作者，我希望每条非清除 `character` 命令都显式声明完整组合列表，以便命令可以独立解释而不依赖隐藏的最后组合记忆。
4. 作为剧本作者，我希望更换同一角色的组合列表时仍然保持角色身份，以便自然表达换装、表情变化和状态切换。
5. 作为剧本作者，我希望可以清除指定角色或全部正式角色，并且不误删自由立绘、Live2D 或 Spine 对象。
6. 作为剧本作者，我希望 `character` 与 `changeFigure` 共用按 ID 替换、变换、效果和动画能力，以便复用既有演出知识和素材。
7. 作为模板作者，我希望在角色目录中集中声明画布、静态部件和组合预设，以便让一个角色的资源结构保持内聚。
8. 作为模板作者，我希望组合项按书写顺序和预设展开顺序叠加，以便明确控制遮挡关系。
9. 作为模板作者，我希望重复引用的部件不会被隐式去重，以便表达需要重复绘制的特殊效果。
10. 作为模板作者，我希望预设可以递归复用其他预设，以便减少常用服装、身体和表情组合的重复声明。
11. 作为模板作者，我希望部件可以声明精确 `width`、`height`，以便直接表达槽位尺寸和必要的非等比拉伸，而不必预先加工资源。
12. 作为模板作者，我希望同一角色的不同立绘组可以各自声明合成画布，以便每组都以自己的默认底图尺寸合成头像等覆盖层。
13. 作为模板作者，我希望未来能够在同一组件组中声明多个变体，例如 `face.smile` 和 `face.sad`，以便为后续局部切换表情预留稳定的模板方向。
14. 作为玩家，我希望角色资源尚未加载或合成完成时游戏仍能继续，以便网络或设备性能不会让剧本流程停顿。
15. 作为玩家，我希望读档后游戏立即恢复流程，即使部分角色组合仍在后台准备，以便读档体验与普通立绘保持一致。
16. 作为引擎维护者，我希望角色模板 JSON 不进入普通 figure 的资源类型判断，以便避免被误认成 Live2D 模型。
17. 作为引擎维护者，我希望相同模板和相同组合的并发请求共享一个任务，以便避免重复加载和重复 Canvas 合成。
18. 作为引擎维护者，我希望过期的异步组合结果不能覆盖同一角色的最新请求，以便快进和连续换装时舞台状态保持正确。
19. 作为引擎维护者，我希望组合完成后只向 figure 系统交付普通图像，以便不复制现有立绘渲染、变换和动画实现。
20. 作为既有游戏作者，我希望原有 `changeFigure` 对普通图片、Live2D 和 Spine 的资源路由与模型参数保持不变，以便不使用旧整图面部参数的剧本无需迁移。
21. 作为测试维护者，我希望能从一条完整 `character` 场景语句验证 Figure Target 来源和最终图片，以便测试外部行为而不是内部缓存或 Canvas 调用细节。
22. 作为模板作者，我希望用睁眼闭嘴底图加少量眼睛、嘴替换片声明眨眼和口型，以便避免为每个组合导出多张完整立绘。
23. 作为玩家，我希望 Character 位图的眨眼与说话可以同时发生，且说话结束后只让嘴型恢复闭合、眨眼继续运行。
24. 作为动态模型剧本作者，我希望 Live2D 与 Spine 完全不进入新的位图面部运行时，以便现有模型行为保持不变。

## Implementation Decisions（实现决策）

- 新增独立的 `character` script；正式语法为 `character: <角色名>/<组合项>[,<组合项>...] [figure 参数...];`，不使用 `-preset` 参数。
- 角色名是角色 Figure 来源的身份。同名来源在当前 Figure Target 中最多存在一个；命令写入前移除其他目标中的同名来源。
- `character` 完整复用 WebGAL 的 Figure 目标选择：显式 `-id` 决定自由 Figure Target；命名位置参数决定基础位置，并在没有 `-id` 时使用 `fig-<position>` 目标；没有位置参数时默认 `center`。`-id` 与命名位置都不参与角色身份判断。
- 另一个角色来源或普通 `changeFigure` 写入同一 Figure Target 时直接替换该目标；同一角色来源改用新目标时先清除旧目标。
- 同一角色换组合、换位置或迁移 Figure Target 时沿用普通 Figure 的交叉切换语义：旧容器非阻塞退场，新图片就绪后挂载并执行入场；过渡期间允许同一角色同时存在一个正在退出和一个正在进入的 Figure 容器。显式 `character -clear` 同样允许旧容器完成非阻塞退出动画。
- 不新增独立 `characters[]`、角色舞台绑定集合或角色专属演出状态。角色名与完整组合列表作为 Figure 来源描述保存在现有目标状态中，`transform`、动画、滤镜、层级和混合模式继续使用现有 figure 演出状态。
- 每条非清除 `character` 命令都必须提供非空组合列表；缺少组合列表时记录作者错误且不改变舞台状态。只修改变换、效果或动画时也重复声明当前完整组合。
- `character: <角色名> -clear;` 扫描当前 Figure Target 并移除匹配的角色来源；目标不存在时安全地视为空操作。`character:none;` 移除全部角色来源。
- 角色清除立即提交 Figure Target 状态，存档与后续舞台同步不能复活已清除来源；已有退出动画可以继续非阻塞播放。
- 角色清除不影响普通 `changeFigure`、自由立绘、Live2D 或 Spine 对象。
- 斜杠后的组合项可以引用静态部件或组合预设。预设在引用位置递归展开，顺序保留，重复引用保留；缺失引用和循环引用属于模板错误。
- `character` 把稳定来源描述和静态图片通用参数直接委托给 OpenWebGAL dev 的 `changeFigure`；按 ID 替换、变换、滤镜、层级、混合模式、进出场动画和身份判定均以上游实现为唯一主链。组合变化只替换角色当前普通图像，不改变角色身份。
- 用户动画资源继续使用社区原有的纯帧数组格式，加载后统一相对目标已结算 transform 演出；不增加结构化资源格式或用户侧绝对帧开关。引擎内部动态时间线不增加资源标记，也不恢复 `keepOffset` 脚本参数。
- 委托前过滤 `motion`、`skin`、`expression`、`bounds`、`blink`、`focus` 和其他 Live2D、Spine 专属参数；这些脚本参数仍只服务普通 `changeFigure` 的相应资源类型。组合角色的位图面部资源只能由模板 `facialRig` 声明。旧整图 `mouthOpen`、`mouthClose`、`mouthHalfOpen`、`eyesOpen`、`eyesClose` 与 `animationFlag` 已从 `changeFigure` 删除，不再是任何 Figure 类型的脚本参数。
- 不提取或维护第二套通用 Figure Target presentation 模块。Character 只保留选择符解析、同名来源管理、模板合成、缓存和异步交付；上游 `changeFigure → StageState → Pixi sync → animation` 保持主导。
- 角色模板使用版本化 `figure.json`，声明回退画布、静态部件、组合预设和可选 `facialRig`。对象预设可声明自己的画布与 rig；旧数组预设和直接部件选择继续使用顶层回退画布与顶层 rig。部件和替换片路径都相对模板目录解析，且只接受静态位图。
- `facialRig` 的 `eyes` 与 `mouth` 可以独立省略，但整个 rig 至少包含一个分支。每个分支都声明非负整数 `x/y` 和正整数 `width/height`，矩形必须完全位于最终组合画布内。`eyes.closed` 与 `mouth.open` 分别是分支必需图片；`eyes.half` 和 `mouth.halfOpen` 可选，省略时分别直接进入闭眼片和复用张嘴片。
- 对象预设一旦声明自己的画布或 `facialRig`，就完整拥有该组合的呈现坐标，不隐式继承顶层 rig。一次选择不得混用不同预设画布或不同预设 rig。
- 静态部件的尺寸字段使用三种互斥模式：不声明 `scale`、`width`、`height` 时采用图片原始尺寸；只声明正数 `scale` 时等比缩放；成对声明正数 `width`、`height` 时按精确尺寸绘制并允许非等比拉伸。只声明一个精确尺寸或将精确尺寸与 `scale` 混用属于模板错误。
- 组合采用普通 `source-over` 顺序叠加，越出组合画布的像素裁剪，输出尺寸等于所选预设画布；预设未声明画布时回退到模板顶层画布，并保留透明通道。一次组合选择不得混用多个不同的预设画布。
- 角色来源解析器负责模板读取、校验、预设展开和异步合成；Character source adapter 只在 Pixi 同步识别稳定来源前缀并交付最终普通图像。除此以外仍执行上游 Figure 同步和动画逻辑，普通图片、Live2D 与 Spine 不进入该 adapter。
- Character source adapter 可以在普通组合图片旁交付解析后的 `facialRig` 资源 URL。`Facial Rig` 仅指 Character 位图的替换区域和图片资源，不包含 Live2D，也不拥有计时；位图面部适配器在同一 Figure 容器内挂载眼睛、嘴替换 Sprite，使其自然继承位置、缩放、透明度、滤镜、混合模式、层级和进退场动画。
- 单个 `FigureFaceRuntime` 以 Character 位图 Figure Target 为身份管理面部附着与说话租约。语音轨道异步预分析整句 PCM 包络并按媒体 `currentTime` 采样；分析等待或失败期间使用同样按 `currentTime` 随机访问的确定性三档时间轴。文本轨道按文字、标点与台词时长生成确定性嘴巴张开度，短句同步首帧即能张嘴；眨眼轨道在 Figure 附着期间独立生成眼睛睁开度。二者合成为一次原子 `FacePose` 提交。位图适配器以迟滞量化到三档替换片，并要求闭合与全开之间经过半开。Live2D 与 Spine 不附着本运行时。
- 新的同目标附着或说话租约取代旧租约，过期释放和迟到的异步语音分析不得覆盖新状态。说话停止只恢复闭嘴；Figure 开始逻辑退场时按实例 UUID 立即停止眨眼并释放适配器，旧退场容器不能继续占用原 target。面部运行时、轨道、姿态、计时器、解码结果和适配器不进入 StageState 或存档。
- 普通 `changeFigure -blink` 继续由 Live2D 原有路径处理，不同步到 Character 位图面部运行时。
- 任一位图面部分支的必需替换纹理加载失败时记录一次可定位的错误并只关闭该分支；可选半帧失败时复用该分支的完整替换片。两种情况都保留组合底图和另一分支继续工作；语音分析失败时继续确定性媒体时间轴口型，单个适配器呈现失败时只隔离该 Figure，均不得阻塞语音播放、剧本、读档或角色组合交付。
- `figure.json` 永远不作为 figure URL。普通 `.json` figure 的 Live2D 识别逻辑保持原行为。
- 模板读取、部件加载、组合合成、首次显示和读档恢复均不阻塞剧本执行。实现复用普通立绘的非阻塞加载策略，而不是增加等待组合完成的全局屏障。
- 同一游戏进程内缓存已校验模板、已生成组合和进行中的同键任务。游戏刷新或进程结束后缓存失效。
- 首期不写入浏览器持久化存储；不引入 `localforage`、IndexedDB 组合库、持久化 WebP、缓存开关或清理按钮。
- 可在现有资源预取窗口中异步读取角色模板、预取其部件并低优先级预热组合；实际可见请求优先，预热不得阻塞游戏。
- 每个 Figure Target 的异步来源解析需要可比较的新旧修订；完成的旧任务可以进入本轮缓存，但只有仍与目标当前来源描述一致的结果可以交付。
- 存档沿用现有 Figure Target 与演出状态，只把角色名、完整组合列表及既有动态模型配置保存为稳定状态；不保存 Blob URL、Canvas、Pixi 纹理、FacePose、语音/眨眼轨道或位图面部适配器。
- 读档立即恢复 Figure Target 描述并异步重建组合；单个来源失败不能中止其他舞台对象恢复，也不能阻塞后续剧本。
- `components.<group>.<variant>` 作为后续局部部件切换的模板扩展方向。首期不定义局部切换命令，也不在运行时维护独立可演出的部件树。
- 既有 `changeFigure` 继续处理普通图片、Live2D 与 Spine，也继续接受 Live2D `-blink` 时序配置，但不承担正式角色组合语法。使用已删除整图 `mouth*`、`eyes*` 或 `animationFlag` 的位图剧本需要迁移到 Character `facialRig`；Live2D 与 Spine 继续使用各自原有模型路径，不是本迁移的目标。
- 私有 `composeFigure` Demo、`-composite` 参数及其专用解析、缓存和测试不进入主分支兼容范围，可以删除。

## Testing Decisions（测试决策）

- 主测试 seam 只有一个：输入包含 `character` 的完整场景语句，观察上游 Figure Target 中的稳定来源描述、演出参数和 Character adapter 最终交付的普通图像。
- 主缝隙测试只断言外部行为：同名来源唯一、完整组合选择、figure 参数、非阻塞执行、异步结果新旧顺序和存档恢复；不直接断言私有 `Map`、Promise 队列、Canvas 绘制调用次数或内部 Pixi 对象结构。
- 解析器测试沿用现有场景解析测试模式，覆盖命令识别、角色名、完整组合列表、figure 参数，以及缺失或非法选择符的拒绝行为。
- 规则层只保留必要的纯测试，覆盖有效模板、缺失引用、循环引用、递归展开、绘制顺序、重复项和路径边界。
- 模板与合成测试覆盖原始尺寸、等比 `scale`、精确 `width`/`height`、非等比拉伸、预设独立画布、旧数组预设回退，以及单边尺寸、尺寸模式混用和一次选择混用不同预设画布的拒绝行为。
- 面部 rig 规则测试覆盖顶层回退、预设作用域、矩形画布边界、必需与可选帧、角色目录路径边界，以及一次选择混用不同 rig 的拒绝行为。
- Figure 面部运行时测试覆盖语音与眨眼两条独立轨道的原子姿态提交、先说话后附着、同目标租约替换、过期释放隔离、停止说话后继续眨眼、按 Figure UUID 的退场解绑，以及分析或呈现失败的 best-effort 降级。
- 语音信号测试覆盖固定 50ms PCM 时间线、按媒体 `currentTime` 任意采样、PCM 等待与失败时的确定性时间轴降级、极短文本首帧、文本端点闭嘴与标点停顿、三档口型迟滞，以及闭合与全开之间必须经过半开。
- 位图面部适配器测试覆盖小纹理单次加载、眼嘴并行、缺少半帧回退与单分支纹理失败；另以兼容性测试确认 Live2D 与 Spine 未接入新运行时。
- 运行时测试覆盖同名角色来源重复调用不会占用两个 Figure Target、换组合时更新来源描述，以及不同角色来源可以独立存在。
- 运行时测试覆盖不同角色来源或普通 `changeFigure` 写入同一 figure ID 时直接替换目标、同一角色来源更换 ID 时旧目标进入退场且新目标可以同时入场，以及缺少完整组合列表的命令不改变目标。
- 运行时测试覆盖定向清除、全部清除、不存在目标的空操作、退出动画期间逻辑状态已移除，以及清除不影响非角色 figure。
- 动画测试覆盖用户动画与目标 transform 的相对合成，以及改名退场目标从实际 Pixi 容器读取合成基准。
- 非阻塞测试使用可控的未完成模板、图片或合成 Promise，验证命令执行和读档流程已经继续；Promise 完成后再验证仍匹配 Figure Target 当前来源描述的结果被应用。
- 竞态测试先发起旧组合，再发起新组合，并让旧任务最后完成，验证旧结果不能覆盖新组合。
- 缓存测试通过重复发起同键请求观察只产生一个外部合成结果；失败请求不得成为永久失败缓存，后续请求可以重试。
- figure 边界测试验证角色模板 JSON 从未传入普通 figure 资源解析，而合成结果以普通图片进入现有立绘路径。
- 兼容性测试覆盖既有 `changeFigure` 图片、Live2D 和 Spine 资源路由以及 Live2D `-blink` 时序配置；不为已删除的整图 `mouth*`、`eyes*` 与 `animationFlag` 保留兼容测试。

## Out of Scope（非目标）

- 浏览器持久化组合缓存、磁盘缓存、IndexedDB、`localforage`、持久化 WebP 编码、玩家缓存设置和缓存清理。
- 本轮内存缓存的 LRU、容量上限、内存池和自动回收策略。
- 阻塞剧本、读档或舞台恢复直到角色组合完成。
- 将 `figure.json` 作为普通 figure URL，或修改既有 `.json` Live2D 路径语义。
- 合成 GIF、APNG、视频、SVG、Live2D、Spine 或多个动态模型。
- 任意部件级独立演出、脚本局部替换命令、骨骼变形、Live2D、Spine 和通用运行时部件树；相关资源类型专属 `changeFigure` 参数不进入 `character`。本规格只允许模板预声明的眼睛、嘴矩形替换层。
- 同名角色的多个舞台实例，以及通过旧 `changeFigure` 或私有 `composeFigure` 入口创建正式组合角色。
- 对无效手写模板进行隐式修复或尽力兼容。
- 运行时文件监听，以及自动发现引擎外直接替换的部件文件。
- 把共享规则包、Node 指纹工具或资源指纹算法作为首期交付的硬性前提。

## Further Notes（补充说明）

- 本规格覆盖 Issue #1010 正文中与后续仓库成员评论冲突的方向：组合入口由 `changeFigure` 改为 `character`，角色选择符作为既有 Figure Target 的可恢复来源描述而不是独立舞台状态，持久化缓存退出首期范围，读档恢复不再等待组合完成。
- 评论中的 `character: yuki -preset=summer_uniform -left;` 是早期方向示例；正式选择符采用 `character: yuki/summer_uniform,xxx,yyy [figure 参数...];`，目标参数继续支持默认中心、命名位置和显式 `-id`。
- `components.<group>.<variant>` 只承诺模板演进方向。默认变体、局部切换参数、组内互斥规则和缓存键扩展需要后续单独规格。
- 本地维护分支与 WebGAL 主分支并不完全一致。实施时只删除与私有 `composeFigure` Demo 和 `-composite` 参数直接相关的代码，不自动删除其他私有功能。
